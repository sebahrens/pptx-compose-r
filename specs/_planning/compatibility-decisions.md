# Compatibility Decision Register

This register is the V1 checklist required by [003](../003-cleanroom-process.md).
It keeps observable legacy compatibility separate from core PPTX/OPC correctness.

Compatibility entries must be updated before closing any V1 compatibility bead.
Every entry is classified with the [003 behavior matrix](../003-cleanroom-process.md#behavior-matrix):
`must-match`, `should-match`, `intentionally-different`, or `unsupported`.

## Update Rules

- Add or update a row whenever a compatibility test, fixture, retained CLI
  behavior, or Node binding relies on observable legacy behavior.
- Link each row to the spec, test or fixture plan, and bead that owns the behavior.
- Do not implement compatibility quirks in core correctness APIs. Keep them in the
  JSON/Node compatibility surfaces unless the row explicitly says otherwise.
- The agent CLI is not a legacy compatibility surface. Removed legacy conversion
  commands (`to-json`, `to-pptx`, and `convert`) stay out of the CLI plan.
- If a legacy behavior is unsafe or would corrupt a deck, classify it as
  `intentionally-different` or `unsupported` and require a structured diagnostic.

## Coverage Checklist

Before any V1 compatibility bead closes:

- [ ] All behavior relied on by [002](../002-observable-current-behavior.md) has a row above.
- [ ] All compatibility tests listed in [080](../080-testing-and-fixtures.md#compatibility-tests) map to at least one row above.
- [ ] Each row has a tier, a Rust V1 decision, and at least one owning bead.
- [ ] Any `intentionally-different` row documents migration impact.
- [ ] Any `unsupported` row identifies the diagnostic or compatibility boundary.
- [ ] Compatibility code remains isolated from core correctness APIs and the agent CLI.
